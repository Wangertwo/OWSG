# 意图路由层：从自然语言输入到系统意图

## 页面定位

意图路由层负责把玩家的自然语言输入，转化为系统可执行的明确意图。

它不是简单的关键词匹配，而是判断这句话应该交给哪个模块处理：本地玩法系统、NPC 规则系统、商店系统，还是后端大模型。

---

## 设计目标

- 将模糊的玩家表达转化为稳定的系统意图
- 区分“文本生成”和“玩法状态变更”两类行为
- 避免宽泛关键词导致误判，例如把“这条渔闻不对”误识别为“请求新渔闻”
- 让每次路由都有明确结果，便于调试和扩展

---

## 推荐实现方式

采用统一的意图解析服务，将路由逻辑从聊天控制器中抽离出来。

```text
玩家自然语言输入
        ↓
文本归一化
        ↓
NpcIntentResolutionService
        ↓
输出结构化意图
        ↓
分发到对应系统
```

意图解析服务只负责识别意图和决定处理路径，不直接修改游戏状态。

真正的状态变更由具体玩法服务完成，例如渔闻服务、商店服务、任务服务。

---

## 结构化路由结果

意图解析服务输出统一的数据结构：

```csharp
public class NpcIntentResolution
{
    public NpcIntent intent;
    public float confidence;
    public string reason;
    public bool shouldUseBackend;
    public string chatMode;
}
```

其中：

- `intent`：识别出的系统意图
- `confidence`：本次意图判断的置信度
- `reason`：命中的关键词、上下文或规则原因
- `shouldUseBackend`：是否需要请求后端大模型
- `chatMode`：后端对话模式，例如 `default_chat` 或 `fishing_rumor`

---

## 意图优先级

意图识别应采用优先级机制，而不是平铺式关键词匹配。

推荐优先级如下：

```text
1. 验真失败反馈
2. 采信渔闻验证
3. 信任交易 / 卖鱼
4. 明确请求渔闻
5. NPC 功能问答
6. 普通自由对话
```

高优先级意图通常会触发游戏状态变化，必须优先识别。

低优先级意图主要用于文本回复，可以交给规则系统或后端大模型处理。

---

## 示例：从自然语言到系统意图

玩家输入：

```text
这条渔闻不对
```

路由过程：

```text
文本归一化：这条渔闻不对
命中上下文：渔闻
命中反馈词：不对
```

路由结果：

```text
intent = FailedRumorFeedback
shouldUseBackend = false
reason = 命中“渔闻”上下文 + “不对”失败反馈词
```

该输入不应进入“请求新渔闻”流程，而应进入“验真失败反馈”流程。

原因是“不对”“不准”“失败”“没钓到”等否定反馈词，比“渔闻”“消息”这类宽泛主题词拥有更高优先级。

---

## 意图分发路径

```text
FailedRumorFeedback
→ 调用 FishingRumorService
→ 渔夫道歉、发放补偿、请求生成新渔闻

AcceptRumorVerification
→ 调用 FishingRumorService
→ 设置当前采信渔闻，进入验真状态

TrustedFishTrade
→ 调用 MerchantShopInteractable / ShopService
→ 打开信任交易商店，应用信任鱼价

AskFishingRumor
→ 请求后端大模型
→ chatMode = fishing_rumor
→ 生成结构化渔闻内容

FreeChat
→ 请求后端大模型
→ chatMode = default_chat
→ 生成普通 NPC 对话回复
```

这种分发方式可以保证：玩法动作由本地系统确定，开放式表达由大模型生成。

---

## 为什么不让大模型直接控制玩法动作

大模型适合生成自然语言内容，但不适合直接决定游戏状态变化。

例如以下行为必须由 Unity 本地系统裁决：

- 是否采信一条渔闻
- 是否判定验真成功或失败
- 是否发放补偿物品
- 是否解锁信任交易
- 是否打开商店界面
- 是否修改鱼类出售价格

后端大模型可以参与“表达”和“内容生成”，但核心状态必须由本地服务校验和执行。

---

## 相比当前实现的优化点

当前实现中，部分路由规则分散在聊天控制器内部，例如采信验证、失败反馈、信任交易、渔闻模式判断等。

推荐方案将这些判断集中到独立的意图解析服务中，形成更清晰的职责边界：

```text
ChatFlowController
负责收发消息和流程调度

NpcIntentResolutionService
负责识别玩家意图

FishingRumorService / ShopService
负责执行具体玩法逻辑

AI Gateway
负责生成开放式 NPC 文本或结构化渔闻内容
```

这样可以减少聊天控制器的复杂度，也便于后续新增任务、战斗、建造、交易等更多意图。

---

## 方案价值

**可控性更强**

核心玩法逻辑不依赖大模型自由判断，避免状态不可控。

**可维护性更好**

意图规则集中在统一服务中，新增或调整意图时不需要反复修改聊天主流程。

**误识别更少**

通过优先级机制，可以避免“渔闻不对”被误判成“请求渔闻”。

**调试更方便**

每次路由都输出 `intent`、`confidence` 和 `reason`，可以快速定位误判原因。

**扩展性更高**

未来可以继续接入任务、建造、狩猎、交易等系统，形成统一的自然语言交互入口。

---

## 总结

意图路由层是自然语言输入和游戏系统行为之间的中间层。

它的核心价值不是“让 AI 理解所有语言”，而是把玩家表达稳定映射到有限、明确、可执行的系统意图。

推荐采用：

```text
统一意图解析服务
+ 优先级规则
+ 本地状态裁决
+ 大模型文本生成
```

通过这种方式，可以构建一个可控、可扩展、可调试的 NPC 智能交互系统。
